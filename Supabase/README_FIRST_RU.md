# Настройка Supabase для Hussle — сначала прочитать

В этой версии старые миграции 0001–0008 заменены одним проверяемым bootstrap-файлом:

`migrations/0001_hussle_backend_bootstrap.sql`

Он:

- работает внутри транзакции `BEGIN … COMMIT`;
- очищает частично созданные таблицы, типы, функции, триггеры и известные политики Hussle;
- не удаляет строки из системных таблиц Supabase Storage;
- не удаляет файлы Storage;
- создаёт всю актуальную схему Hussle сразу в согласованном состоянии;
- повторно запускается на новом проекте без необходимости вручную удалять частичные таблицы.

## Порядок

1. В Supabase откройте SQL Editor → New query.
2. Вставьте весь `0001_hussle_backend_bootstrap.sql`.
3. Нажмите Run один раз.
4. После успеха откройте Storage и создайте два PRIVATE bucket:
   - `dog-photos`
   - `vaccination-documents`
5. Не создавайте политики вручную: bootstrap уже создаёт их на `storage.objects`.

## Важно

- Не запускайте старые миграции из предыдущих архивов.
- Не удаляйте записи напрямую из `storage.objects` или `storage.buckets`.
- Объекты Storage удаляются только через Storage API или Dashboard.
